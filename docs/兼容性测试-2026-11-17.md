# 框架兼容性与桥接测试记录

测试时间：2026-11-16 至 2026-11-17，环境为 MuMu 12 / Android 12 / x86_64 的独立克隆实例。

框架候选为 [Vector 官方项目](https://github.com/JingMatrix/Vector)的 v2.2-3119 Debug 预发布构建；对照为此前实例中安装的 LSPosed。以下结论仅针对当时测试版本与状态。

| 条件 | 观测结果 |
| --- | --- |
| Vector，不加载模块 | 目标应用进入并保持登录页 |
| Vector，仅加载不执行 Hook 的诊断模块 | 日志确认模块加载，目标应用保持登录页 |
| Vector，加载原版 Robot Hook | 日志出现 `RobotHook: armed`、`bridge connected`，目标应用保持登录页 |
| 同一实例、相同未登录状态，改回旧 LSPosed 加载同一 Robot Hook | 启动后进程退出，多次复现 |

该目标应用是运动世界 7.3.61（versionCode 400）。账号换设备保护阻止了后续登录，因此**没有验证登录后的运动流程，也没有提交运动记录**。这组结果只表明切换框架改善了当时的启动兼容性。

此外，在关闭第三方目标应用时，用自有 Robot Bridge Test 做了短时本地模拟。原始快照与 Hook 读取结果的步数、步频、速度、方向、加速度计和陀螺仪数据一致；Android Location 使用预期的坐标转换。模拟随后已停止。

这些桥接实测使用 0.1.0 原始模块，证明其与该 Vector 构建的基本互操作；0.2.0 的公开发布验证另见 Release 说明。框架更新、目标应用更新或 Android 版本变化后，需要重新验证。
