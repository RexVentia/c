# 安装与使用说明

适用版本：RobotSimulator / Robot Hook / Robot Bridge Test 0.2.0。

## 一、准备环境

本次验证使用 MuMu 12 的 Android 12、x86_64 实例。建议使用专门的开发测试实例。

只使用路线绘图与模拟时，安装主程序即可。需要 Hook 时，先确认实例中的 Root 和 Xposed 兼容框架已正常运行，再安装本项目的 Hook 模块。可参考 [Vector 官方项目](https://github.com/JingMatrix/Vector)的安装说明；本项目不会自动安装或修复框架。

## 二、安装三个组件

从 [Releases](https://github.com/RexVentia/c/releases) 下载同一版本的三个 APK，拖入 MuMu 安装即可。使用 ADB 的开发者也可执行：

```powershell
adb -s <当前实例的序列号> install -r RobotSimulator-0.2.0-debug.apk
adb -s <当前实例的序列号> install -r RobotHook-0.2.0-debug.apk
adb -s <当前实例的序列号> install -r RobotBridgeTest-0.2.0-debug.apk
```

请从 MuMu 的实例信息确认实际 ADB 地址，不要直接照搬其他实例的端口。若提示签名不匹配，说明已安装版本与下载包使用了不同签名；先保留需要的本地数据，再决定迁移方式，避免直接卸载丢失路线。

## 三、填写个人地图 Key

1. 打开 RobotSimulator，点击右上角“地图设置”。
2. 记下页面提供的包名 `com.robot.simulator` 和证书 SHA1；内容支持长按选择复制。
3. 在[高德开放平台](https://console.amap.com/)创建应用，新增 **Android 平台 SDK** Key，按当前 APK 填写包名和对应签名 SHA1。申请流程见[官方说明](https://lbs.amap.com/api/android-location-sdk/guide/create-project/get-key/)。
4. 将 Key 填回应用并保存。Key 输入默认遮挡，保存在本机应用数据中。
5. 首次配置后可创建路线；更换已经用过的 Key 时，请完全退出应用再重新打开。

公开 APK 没有内置作者的 Key。源代码编译者也可设置本地 `amap.api.key`；公开构建参数 `-PpublicBuild=true` 会忽略该默认值。

## 四、画路线

进入“路线”→“新建路线”。首次加载地图会显示地图服务说明，由使用者决定是否同意。定位到想要测试的区域，进入绘制状态后按住鼠标拖动，松开结束一次绘制；可以撤销或重新绘制。输入名称并保存。

路线长度由实际经纬度计算，不是屏幕上的像素长度。

## 五、配置并运行模拟

在“参数”页选择已保存路线，然后设置：

| 参数 | 含义 |
| --- | --- |
| 总步数 | 这次模拟最终完成的步数，必须为正整数 |
| 平均步频 | 120–151 步/分钟 |
| 步频起伏幅度 | 不同公里段围绕平均步频的变化幅度 |
| 配速起伏幅度 | 不同公里段的配速变化百分比；0 表示各公里平均配速一致 |
| 随机种子 | 同一路线和参数使用同一种子，得到相同的模拟结果 |

总时长约为 `总步数 × 60 ÷ 平均步频` 秒；平均速度为 `路线长度 ÷ 总时长`。平均速度应在 2–5 m/s 范围内，超出时会显示建议步数。点击“填入建议步数”可自动填入可用值。

预览区域显示步频曲线和各段配速。点击“开始模拟”后，可在运行页暂停、继续或提前停止。窄窗口需要滚动数据区域才能看到控制按钮。结束或提前停止后，可在“历史”查看本地记录。

## 六、验证 Hook 和桥接

1. 在已激活的 LSPosed / Vector 管理器中启用 Robot Hook。
2. 首次验证只勾选 `Robot Bridge Test`（`com.robot.simulator.testtarget`）为模块作用域。
3. 完全关闭并重新打开 Robot Bridge Test，必要时按框架要求重启实例。
4. 在主程序中启动一段模拟，然后切换到 Robot Bridge Test。
5. 上半部分应显示“连接：是”，快照序号持续增加；下半部分的步数、步频、速度、方向和传感器数据应跟随上半部分变化。

**经纬度不要求逐字相等**：原始快照为 GCJ-02，测试程序读取的 Android `Location` 为 WGS-84。只有启动了模拟、序号大于 0，才能有效检查 Hook；尚未开始时的 0 或 -1 不能单独作为失败证据。

通过自带目标测试后，再在授权范围内为自己的测试程序设置作用域。主程序自身、系统界面和框架管理器不应作为测试目标。

只验证 AIDL 时不需要 Hook。系统级测试定位是另一条通道，需要在 Android 开发者选项中选择模拟位置信息应用；它不会自动获得，也不会移除系统模拟位置标记。

## 七、常见问题

| 现象 | 检查方法 |
| --- | --- |
| 地图为空、鉴权失败 | 检查 Key 服务类型、包名、当前 APK 的 SHA1 和网络；更换 Key 后彻底重启应用 |
| 仍提示缺少 Key | 在“地图设置”保存；如果停留在之前的缺 Key 页面，返回路线页后重新进入 |
| Hook 列表里没有模块 | 确认已安装 RobotHook APK，并检查框架是否正常运行 |
| 连接为“否” | 打开主程序、点击测试页“重新连接”，核对两个应用是否在同一实例 |
| 有原始数据但读取结果仍为默认值 | 检查模块启用和作用域，重启目标程序后再测试 |
| 两组位置略有差异 | 先检查 GCJ-02 / WGS-84 坐标转换，不要直接认定为地图偏移 |
| 目标应用退出或提示环境异常 | 本项目不保证第三方应用兼容；先用自带测试目标隔离问题 |
| 找不到暂停/停止按钮 | 在运行页右侧或下方的数据区域向下滚动 |
| 更新提示签名冲突 | 当前版本与新 APK 签名不同，先保存需要的数据再处理安装迁移 |

## 八、更新与反馈

更新时优先使用同一来源、同一签名的一套安装包，使用覆盖安装保留本地数据。更新后重启目标测试程序。反馈问题请提供组件版本、Android 版本、框架版本、复现步骤和脱敏日志，不要附带地图 Key、账号凭据或完整实例备份。
